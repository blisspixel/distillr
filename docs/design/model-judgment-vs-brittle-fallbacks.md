# Model judgment vs brittle fallbacks: use what they have, degrade honestly

> Status: design charter + remediation plan. Sibling to [`agentic-balance.md`](agentic-balance.md), which draws the rule-vs-judgment line; this doc applies that line to one recurring violation - **deterministic keyword/regex heuristics standing in for a semantic judgment** - and plans the fix. Triggered by a June-2026 audit (Nick) that found the eval grader was not the only brittle proxy. Research → plan → fix; the fix is staged, not a hasty rip-out.

## The principle

Three rules, in order:

1. **A semantic judgment is a model's job.** "Is this video on-topic / practical / a credible leak?", "is this paper substantive?", "how good is this analysis?" - none of these have a regex answer. They are model calls (cloud or local). Encoding them as keyword lists is the "brittle proxy" failure mode named in [`agentic-balance.md`](agentic-balance.md).
2. **Use what the user has - never assume.** Do not assume a cloud key. Do not assume a local model. The router already abstracts provider+model behind workload tags and supports cloud (`xai`, `gemini`, `anthropic`) *and* local (`ollama`, `lmstudio`, no key). Judgment routes to **whatever model is configured**: cloud preferred for quality, local when that is what they have. A feature asks the router "can I get a model for this workload?", not "is `XAI_API_KEY` set?".
3. **When there is genuinely no model, degrade honestly - don't fake it.** A brittle keyword score dressed up as a quality ranking is worse than an honest non-semantic order, because it hides the degradation. With no model available, fall back to a transparent, clearly-labeled deterministic order (recency / engagement metadata) and say so. Never present a keyword heuristic as if it were judgment.

This is invariant #6 ("LLM proposes, Python decides") read correctly: Python decides the *structural* things (dedup, thresholds, ordering arithmetic, output labels); the model makes the *semantic* call; and the no-model path is honest about being a downgrade.

## What June 2026 practice says

The graceful-degradation literature gives an explicit fallback ordering, and it puts rule-based heuristics dead last:

1. Alternative model, same capability tier
2. Different provider (… → **local model**)
3. Cached responses (labeled stale)
4. **Rule-based deterministic responses** - only after every model option is exhausted
5. Human escalation

Two findings matter here. First, **keyword/heuristic scoring as a fallback is a named anti-pattern** - acceptable only at tier 4, after cloud *and* local models are unavailable. Second, **every degraded response must be labeled**: "acknowledge unavailability, explain reduced capability, annotate uncertainty." Silent degradation "creates undetectable failure modes."

distill today does the inverse of both: the moment the *cloud* key is missing it drops straight to tier-4 keyword scoring, **skips the local-model tier entirely**, and **labels nothing**.

The two HIGH rows are the real problem and share one root cause: **`ranking.py` asks `config.xai_api_key` instead of asking the router whether any model is available.** A user who set `provider=ollama` has an empty `xai_api_key`, so they get keyword scoring as their *primary* ranker while a perfectly good local judge sits idle. And the rumor/skeptical keyword trip-wire then reaches *into* the model path, telling the LLM to be skeptical based on whether the literal word "leak" (or, falsely, "analysis") appears in the query.

## The plan (staged)

**P1 - Route judgment to whatever model exists. SHIPPED 2026-06-14.** The `not config.xai_api_key` gate in `rerank_videos` / `rerank_papers` (and the sibling `report/synthesize.py` hard-abort) now asks the router instead: `_rerank_model_available()` / `_synthesis_model_available()` return True iff `RouterConfig().validate_config(workload)` passes (a keyless local provider is configured, OR a cloud key is present). So an Ollama/LM Studio user gets the model judge, and a local-only user is no longer blocked from synthesis with "XAI_API_KEY not set"; the keyword heuristic is the fallback only when *no* model is configured at all. *(Implementation note: the planned `RouterConfig.has_model_for` helper was inlined as a `validate_config` try/except in the two pipeline helpers because `distill/llm/router.py` is already at the 500-line module-size cap; the capability logic is `validate_config`'s either way.)* Covered by `test_ranking.py::{test_rerank_uses_model_with_local_provider_and_no_cloud_key, test_rerank_videos_falls_back_to_heuristic_when_no_model_available}` and the synthesize equivalents.

**P1 extended to the whole CLI surface (2026-06-14).** The audit found the same `config.xai_api_key` assumption in ~40 sites, not just the two rerank gates -- most damagingly a hard `XAI_API_KEY required` block on the flagship `distill latest`/`learn` flow (`_learning_flow.py`) and on `papers`/`process`/`reprocess`/`watch`/`maintain`/`discover`/`ask`, each of which a local model could serve. A shared `distill/llm/availability.py::model_available(workload)` (does the router's `validate_config` pass?) plus `commands/_helpers.py::require_model(workload)` (the "use what they have" replacement for `require_api_key(config.xai_api_key, ...)`) now back every CLI entry gate and the misleading "deterministic fallback" warnings. Genuinely cloud-specific gates are deliberately left as `require_api_key`: the grok-only eval judge (`eval.py`) and Gemini Deep Research (`research-brief`, `learn.py`). The command-test conftest defaults a keyless local provider so the gate is exercised the way the old key gate was.

**MCP-tool surface swept too (2026-06-14).** The same `if not config.xai_api_key` gate (and the `use_llm=bool(config.xai_api_key)` flags) in the ten model-using MCP tools (`papers`, `discover` x2 + the rerank flags, `synthesis`, `sites`, `topics`, `summaries`, `reports`, `ask`, `watch`) now call `model_available(...)`; the error responses changed from "XAI_API_KEY not configured" to "No model configured (set a cloud key or DISTILL_PROVIDER)". `mcp -> llm` is a downward import to a foundational layer, so the contract holds. An mcp-test conftest mirrors the command one (keyless local provider by default; the no-model tests force a not-implemented provider and now assert "model" not "XAI_API_KEY").

**P2 - honest no-model labeling: DONE 2026-06-14.** The rerank fallback now distinguishes a *forced* degradation from a *chosen* one: `rerank_videos`/`rerank_papers` split the gate so `--no-rerank` (a choice) stays `selected_by="heuristic"`, while *no model configured at all* labels the order `selected_by="no-model"` (`_mark_no_model`). MCP `search_videos` surfaces it to agent consumers as a top-level `ranked_by` field, a per-result `ranked_by`, and a `notice` ("No model configured -- ... not model-ranked ...") when no-model. The MCP `use_llm=model_available("rerank")` sites were changed to `use_llm=True` (redundant, and it had hidden the no-model case by pre-converting it to `--no-rerank`); `rerank_videos` owns availability + labeling now. We kept the deterministic relevance order (it blends relevance/recency/credibility, genuinely useful) rather than stripping to pure recency -- the label is the honesty, not a worse order. Covered by `test_ranking.py::{test_rerank_videos_labels_no_model_fallback, test_rerank_videos_no_rerank_stays_heuristic_not_no_model}` and `test_server.py::test_surfaces_ranked_by_and_no_model_notice`.

**P3 - Kill the regex skeptical trip-wire. SHIPPED 2026-06-14.** `_looks_like_rumor_query` (the keyword list `leak`/`hack`/.../`analysis`) is deleted from both `pipeline/ranking.py` and `commands/_learning.py`, and removed from the `_logic`/`cli` re-export chain. `_auto_skeptical_mode` now keeps only the structural April-1 date guard (a *date*, not a keyword read of the query); `_skepticism_adjustment` and `_heuristic_learning_queries` gate on the explicit `skeptical` flag alone. So a neutral query that happened to contain "analysis" no longer auto-flips skeptical mode and leaks that verdict into the primary rerank prompt -- whether a source is an unverified leak is the model's read (its rubric already weighs credibility), and `--skeptical` remains the explicit user control. Covered by `test_cli_wiring.py::test_auto_skeptical_mode_ignores_rumor_keywords` (the keyword path now returns False) and `test_learning.py::test_auto_skeptical_mode_triggers_on_april_first` (the date guard stays). *(Note: the evidence/prank keyword deltas inside `_skepticism_adjustment` remain as a tier-4 heuristic that only runs under explicit skeptical mode -- that is the MED-severity P4 item, not P3.)*

**P4 - Demote the remaining ranking heuristics + lens inference.** *Lens inference: DONE 2026-06-14.* `infer_lens` and its keyword cue table are deleted from `prompts/lenses.py`; `make_intent` no longer guesses the lens from the goal, it stays the neutral `general` unless the user passes `--lens`. The goal is already carried into every analysis prompt via `focus_directive`, so the model adapts the analysis to the goal regardless of template; the keyword guess added brittleness (it mislabels mixed goals) without adding semantic value. Help text and `docs/usage.md` updated. *Ranking heuristics: DONE 2026-06-14.* `_heuristic_rank` / `_heuristic_rank_papers` and the individual scorers (`_practicality_score`, `_topicality_score`, `_paper_depth_score`) now carry docstrings stating they are brittle keyword/length proxies used ONLY as the tier-4 no-model fallback (the LLM rerank is primary whenever a model is configured, per P1) and are a transparent best-effort order, not a quality judgment. They are kept, not removed, because an honest deterministic order is the legitimate no-model fallback (the evidence/prank deltas in `_skepticism_adjustment` were already gated to explicit `--skeptical` in P3). **P4 complete.** No ranking or lens brittle fallback remains in the primary path; remaining eval-gate statistics ideas are paused unless a concrete regression demands them.

**Sequencing.** P1+P2 together (they are one behavioral change: "model if available, honest order if not"). P3 independently. P4 last, mostly documentation + one deletion. Each stage gated by `distill eval` on the frozen fixtures - the same cost×quality bar the charter requires before changing a rule/model ratio.

## The eval gate itself is the worst offender (2026-06-13 adversarial review)

A three-lens PhD-style panel (LLM-eval methodology, statistics, decision theory) tore apart the claim that the eval judge was "done." The findings converged and are verified against the code:

1. **Inversion (CRITICAL) - FIXED.** `report.py` made the migration recommendation from the deterministic `mean_composite` (a keyword/word-count proxy that `scoring.py:11-16` *admits* is "blind to faithfulness"); the rubric judge only fed the confidence label and could not change the pick. A well-formatted, keyword-stuffing, *unfaithful* output cleared the gate. **Fixed:** migration now requires model-judged faithfulness plus pairwise at-par judging; no judge signal means fail closed. The deterministic composite is advisory only and cannot decide or veto migration. Covered by `test_report.py::{test_judge_vetoes_migration_when_it_favors_anchor, test_fail_closed_when_judge_unavailable, test_judge_certifies_migration_when_at_par}` and the Goodhart tests listed below.
2. **Three-way conflict of interest (CRITICAL) - FIXED.** By default `anchor == judge == reference == grok-4.3`: the incumbent judged its own replacement. **Fixed:** `eval.py` auto-judge now refuses a judge that shares the anchor's family *or* is a candidate (a model grading itself); it prefers a different-family cloud model, else a different-family non-candidate local model, else **none** - and with no neutral judge the run fails closed on migrations with an explicit "add a cross-family key or `--judge`" notice. Covered by `test_eval_cli.py::{test_eval_local_only_works_without_cloud_key (now fail-closed), test_eval_auto_judge_picks_cross_family_local_non_candidate}`.
3. **Reference-against-incumbent circularity (HIGH) - FIXED 2026-06-14.** The migration gate was pairwise-vs-the-anchor's-output only, so a *different-but-better* candidate could be penalized for diverging from the incumbent's framing. **Corrected by the June-2026 LLM-judge evidence, which sharpened the fix:** relative (pairwise) judging is the *reliable* mode (ranking correlation rho~0.95) while absolute fine-grained scoring is the *unreliable* one (agreement kappa~0.45) ([Masood, rubric evals 2026](https://medium.com/@adnanmasood/rubric-based-evals-llm-as-a-judge-methodologies-and-empirical-validation-in-domain-context-71936b989e80); [FutureAGI 2026](https://futureagi.com/blog/llm-as-judge-best-practices-2026)). So the original wording ("make absolute the primary decider, pairwise a secondary tiebreaker") would have promoted the *weak* signal over the strong one - the same brittle-proxy mistake, relocated to the model side. **What shipped instead:** an absolute, source-anchored **faithfulness** judge (`judge_faithfulness`, `distill/eval/judge.py`) graded per output against the SOURCE, but deliberately *coarse* (a 3-way `faithful`/`minor`/`unfaithful` categorical, the NLI/entailment shape where absolute judging is reliable - never a fine-grained score). It is an **independent veto floor**: a candidate judged unfaithful on any fixture is refused a migration however it scores or ranks (`report.summarize`'s `_eligible_for_migration`), which decouples "unfaithful" from "diverges from the incumbent's framing" and catches a fluent-but-unfaithful candidate that wins pairwise. **Pairwise stays the primary ranking signal among the faithful** (the reliable mode), not a tiebreaker. Covered by `test_report.py::{test_faithfulness_vetoes_migration_even_when_pairwise_wins, test_faithful_candidate_at_par_migrates, test_less_faithful_than_anchor_migrates_but_tentative}` and `test_judge.py` faithfulness cases. Still open from the original item: dropping the deterministic heuristic prior from the gating pairwise prompt so it stays fully independent of the brittle composite (the prior is currently shown flagged-as-noisy; removing it from the *gating* path is tracked under #4's calibration work).
4. **No statistics / no calibration (HIGH) - 4a REVERTED as fake-rigor 2026-06-14.** N=3 fixtures per workload drove a go/no-go via a bare `>=`. The first attempt (4a) added `distill/eval/stats.py` (a seeded bootstrap CI of the win-rate) + a `_MIN_FIXTURES_FOR_HIGH=8` gate. **That was itself the brittle-junk failure mode and is being removed (product-owner call):** a bootstrap confidence interval over **3 points** is statistical theater (the band is meaningless at that N), `min-N=8` made "high" confidence unreachable so the machinery's only output was "tentative", and `0.45` was an unjustified magic constant. Dressing a tiny sample in statistics to look rigorous is exactly what the charter forbids. **Replacement:** rip out the bootstrap; state the sample size plainly ("N fixtures: advisory, not enough to certify a switch - scale to ~20 to gate on it"); keep the faithfulness veto + pairwise judge (real model judgment). Real statistics wait until the fixture corpus is large enough to make them meaningful (the 1.0 scale-up), and even then must clear `distill eval` against real regressions, not cite a framework. **4b (judge self-consistency) and 4c (calibrate/derive the 0.45 floor) are paused** - not obviously worth their cost/complexity, and not to be built as more machinery; revisit only if a concrete regression demands them.
5. **Goodhart (HIGH) - FIXED 2026-06-14.** The composite no longer decides *or gates*. The earlier "residual" - that the composite still gated eligibility as a floor - was itself the brittle-rule failure mode (a keyword/length floor can wrongly *exclude* a faithful, judge-approved candidate that paraphrases or is terse, the precise "punishing of good paraphrase" the case study names). It is now **removed from the migration decision** in `_eligible_for_migration` and `_confidence`: eligibility is the faithfulness veto + pairwise at-par (both model judges), and the composite survives only as the offline golden-CI regression tripwire and a labeled advisory diagnostic in the report. The `--threshold` flag is demoted to setting that advisory reference; it no longer gates. Covered by `test_report.py::{test_threshold_is_advisory_not_a_gate, test_composite_does_not_exclude_a_faithful_at_par_candidate}`. So no Goodhart surface remains: there is no deterministic surface-form metric left in the gate to optimize against.

The two CRITICAL items are fixed (2026-06-13), the circularity item #3 is fixed (2026-06-14), Goodhart (#5) is fixed, and **#4's bootstrap attempt (4a) was reverted as fake-rigor** (above). The lesson from #3 is a standing rule: *the fix for a brittle rule is not always "add a model" - it is "add the model in the mode the evidence says it is reliable."* And the lesson from 4a: *do not dress a tiny or meaningless sample in statistics to look rigorous.* Pairwise for ranking, coarse absolute for grounding; no fine-grained "quality score", no bootstrap over 3 points, no machinery that gates without clearing `distill eval` against a real regression.

## Roadmap-level brittle GATES (2026-06-14 audit)

A sweep of the *plan* (not just shipped code) found the brittleness concentrated in the eval/quality/verification **gates** - every "is this output good enough?" gate reached for a deterministic scorer. The ROADMAP was edited to forbid this (the "No brittle junk" rule at its top). Findings and dispositions:

| Gate | Brittle because | Disposition |
|---|---|---|
| **Golden-corpus eval gate** (`test_golden_gate.py`) | *audit initially overstated this.* It does NOT score live model output - it scores fixed hand-written goldens for **discrimination** (good golden high, degraded low) + fixture-sync + prompt-builder wiring, all offline (no model). The composite is fine there (testing a scorer on data we control). | **No rework; clarified.** The offline gate stays structural; the rule is *never extend it to score live output on composite floors*. Live-output quality is `distill eval`'s model judges (on-demand, model). ROADMAP + test docstring corrected (an earlier draft wrongly demanded a "model-judged offline gate" - impossible without keys in CI). |
| **Metamorphic robustness pass** (METAL/cosine-≥0.6/perturbation machinery) | measured surface-token stability against cosine thresholds and called it semantic robustness; gated on cosine numbers | **CUT.** Removed from the 1.0 plan; do not build the machinery. ROADMAP updated. |
| **Eval-gate 4a** (bootstrap CI + min-N=8 + 0.45 over 3 fixtures) | statistical theater over a meaningless sample; magic constants | **REVERTED** (item #4 above). |
| **Deterministic verify `--verify strict`** (numeric presence-check) | *audit overstated this too.* "Is the cited number in (or rounding from) the source?" is a legitimate **structural** check the charter allows; it correctly catches invented numbers, and the emit-path design + honest `warn` default rest on it. | **No rip-out (would be an over-correction).** Its narrow limitation (over-refuses *derived* numbers under strict; under-catches wrong-metric numbers) is mitigated by layering the context-aware **entailment tier** (shipped 0.13.0) on top, not by weakening the structural floor or making the regex do arithmetic. ROADMAP corrected. **Lesson: not everything deterministic is brittle - structural/ground-truth checks are correct; only deterministic *scorers faking semantic quality* are the junk.** |
| **§7 "Insights quality check" heuristic** (sections-present? too-short?) | "is this analysis good?" by section-presence + length | **Redefined** to model-judged (verify/eval judges); only a *structural* parseability tripwire stays, advisory. backlog updated. |

The standing rule (now at the top of both roadmap files): **no quality / faithfulness / robustness gate may be a deterministic score.** Model proposes per-criterion verdicts; Python aggregates. Deterministic checks are for parse / receipt-presence / structural facts only.

## What this means for users (and for keys)

distill's judgments need a **model**, not specifically a *cloud* model. A user satisfies that with **either** a cloud key (`XAI_API_KEY` / `GEMINI_API_KEY`) **or** a configured local model (Ollama / LM Studio) - distill detects and uses whichever is present. No cloud key is *required*; `distill doctor` already reports local-inference readiness. The only hard requirement is "some model"; with none, features degrade to honest, labeled recency order rather than pretending. If a specific feature is ever found to genuinely need a capability only cloud models have, that gets called out explicitly rather than silently assumed.
